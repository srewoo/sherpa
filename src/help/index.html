How Sherpa works

Sherpa reads a documentation site once, keeps the whole thing on your computer, and answers questions from it. No account, no server, no cost per question. This page explains what it does, in the order you will meet it.

1. Index a site 2. Ask a question 3. Knowing when to trust it 4. Keeping indexes fresh 5. Finding documentation gaps 6. Which model answers 7. Tuning search quality 8. Troubleshooting

1. Index a site

Open Options → Set up an index and paste the address of a documentation site — the section you want, not necessarily the whole domain. Sherpa checks the site first and tells you what it found before anything is downloaded.

When you press start, Chrome asks permission for that one site. Sherpa requests access per-site at this moment rather than up front, so it never holds access to anything you have not indexed.

What Sherpa does while crawling

  • Obeys robots.txt, including Crawl-delay, and skips pages marked noindex.
  • Fetches about one page per second by default, and slows down further if the site pushes back.
  • Keeps lists, tables, code blocks and headings intact, and strips navigation and cookie banners.
  • Survives a browser restart. A crawl picks up where it left off.
  • Fetches as you, using your existing session — so a site you are signed into is indexed as you see it.

If a site asks you to sign in partway through, Sherpa pauses and says so instead of indexing a wall of login pages.

2. Ask a question

Click the Sherpa icon, or press ⌘⇧K (Ctrl⇧K on Windows), to open the side panel. Ask in your own words — you do not need the documentation's vocabulary.

Click a source and Sherpa opens the real page and scrolls to the exact passage, highlighted. The answer is a starting point; the documentation is the authority.

Asking follow-up questions

Sherpa remembers the previous question in a conversation, so "and for annual plans?" works without repeating yourself. Use the + button to start a fresh conversation when you change topic.

If you have several sites indexed

The dropdown at the top of the panel picks which one you are asking. Sherpa only ever searches the index you have selected — it does not mix sources.

3. Knowing when to trust it

Sherpa is built to be uncertain out loud. There are three things it can do with a question, and it tells you which one happened.

What you seeWhat it means
An answer with citations Sherpa found a strong match and answered from it.
An answer with a note that the match wasn't strong It found something related but not clearly on point. The answer is worth reading and worth checking against the source.
"Not in this index" Nothing scored well enough. Sherpa shows the nearest pages rather than guessing.

A refusal is a useful signal. It usually means a page is missing, and section 5 turns those refusals into a list of what to write.

Sherpa answers only from the pages you indexed. It will not fall back on what the model learned elsewhere, which is why it can refuse at all.

4. Keeping indexes fresh

Options → Indexes lists everything you have indexed, with its size, page count and when it was last updated.

  • Refresh — re-checks the site and only re-reads pages that actually changed. Much faster than a full crawl.
  • Re-crawl — throws the index away and builds it again from scratch. Use it when a site has been restructured.
  • Delete — removes that index and everything derived from it.

Refreshes also run on their own, every 30 days by default (adjustable in Settings). They wait until your machine has been idle for five minutes and stop the moment you come back, so you should never notice one.

If an index shows Needs access, permission for that site was revoked. A background job cannot ask for it back — click the button on that row to re-grant it.

5. Finding documentation gaps

Every question you ask is recorded on your own machine, along with how well Sherpa could answer it. Options → Gap report groups the failures by topic.

Export it as CSV or Markdown to take into a planning session. This data never leaves your device unless you export it yourself.

6. Which model answers

Finding the right pages and writing the answer are two different jobs. Sherpa always does the finding itself, on your device. For the writing it uses the best option available:

TierWhat it doesWhere your question goes
Passages No model at all — shows the best matching passages, quoted exactly. Always available. Nowhere.
Chrome built-in Writes a real answer using Chrome's on-device model, where your Chrome supports it. Nowhere.
Your own API key Best quality. Uses OpenAI, Anthropic or Gemini with a key you supply. To that provider. This is the only case where anything leaves your device.

The panel labels which tier answered, every time. If the tier you chose is unavailable, Sherpa says why instead of quietly using a different one.

7. Tuning search quality

Answer confidence

Each index measures its own confidence thresholds when its crawl finishes, by testing itself against questions no documentation site could answer and seeing how high those score. What counts as a strong match differs between sites, so a single setting cannot fit them all — which is why this is measured per index rather than configured.

You can still override it: Settings → Answer confidence → Use these numbers for every index. Raise the refusal threshold if Sherpa answers things your docs do not cover; lower it if it declines things they do.

Better ranking

Settings → Search quality has three optional additions. Each costs time per question, so each is off by default:

  • Rerank results — re-reads the top matches with a second model that considers your question and the page together. It makes the biggest difference on sites with many near-identical page titles, and it is the slowest option.
  • Rewrite the question — lets the on-device model rephrase your question before searching.
  • Imagine an answer first — searches using a sketch of what an answer would look like, which sometimes matches documentation better than a question does.

Try one at a time. If an option makes things worse for your documentation, turn it off — they all degrade cleanly back to plain search.

8. Troubleshooting

The crawl stopped early and mentions signing in
The site wants a login. Sign in to it in a normal tab, then press Resume — Sherpa uses the session you just established.
It refuses questions I know are documented
Check the site is fully indexed in Indexes. If the page count looks low, the crawl may have been scoped too narrowly or stopped at a login. Otherwise lower the refusal threshold in Settings.
Answers are just lists of passages
No writing model is available, so Sherpa is using the always-available Passages tier. Add an API key in Settings for full answers.
The panel says the index was built with a different model
The search model was changed after this index was built, and the two are not comparable. Re-crawl the index — Sherpa refuses to search it rather than return nonsense.
Answers are slow
Turn off Rerank results in Settings. It is by far the most expensive option, and the first question after opening the panel is always slower while the index loads.
I want it all gone
Settings → Delete everything erases every index, your settings and any stored key. Uninstalling the extension does the same.

Sherpa runs entirely on your computer. See the privacy policy for exactly what is stored and what is sent.
